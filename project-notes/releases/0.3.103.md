# Release 0.3.103 — WebTiles RC editing from Play

Source version **0.3.103**, immutable source tag **`cloudflare-online-v1.100`**. Publication follows [DEPLOYMENT.md](../DEPLOYMENT.md) through the automatic main-triggered Workers Build.

The home screen offers `(edit rc)` beside each advertised Play version after login. It opens the existing editor for the file named by that server's lobby, shares the file with original WebTiles for the same account/version, and returns to the link opened. Servers retain independent files; modes share only the RC file advertised by the server. Save verification, current-server reads on reopen, unsaved-change protection, account-screen editing and controller support remain intact.

The release includes the previously published 0.3.102 critical-health vignette changes. The RC implementation was committed separately and current production main was merged before release preparation. Publication uses an atomic, non-force main/tag push after another authoritative fetch. Other checkouts are left untouched, and the automatic build is the sole deployment path.

## Validation

- `npm run verify` for the RC implementation: TypeScript and **2,347 unit tests passed**, two optional-engine skips.
- `npm run verify:browser` for the RC implementation: **20 browser tests passed**, including desktop/touch server RC reads, exact saves, fresh reads after simulated WebTiles edits, return focus and unsaved-change protection.
- `npm run verify:release` for the integrated release: forced TypeScript, **2,362 unit/deployment tests passed**, production build and **21 browser tests passed**, zero retries, including the full raster matrix and production acceptance.
- Reviewed the integrated diff, source/version links and whitespace. The release retains production's online-only boundary, existing rendering, reduced motion, account storage and the published critical-health changes.

The build retains its existing non-fatal large-chunk warning. Two optional engine tests are skipped because engine artifacts are unavailable. Authenticated public-server RC writes and physical-device acceptance are outside these local checks. Clean-tree guarded packaging, a fresh main check, atomic publication and observed hosted source/bundle/production checks are required before deployment is reported complete.
