# 0.3.124 — Immediate menu entrance and faster publishing

Source tag: `cloudflare-online-v1.121`.

Removed the recorded menu poster entirely. A lightweight CSS dungeon entrance
appears immediately; engine loading no longer waits 800 ms. Loading text yields
to the first live frame and disappears for Still, failures and unsupported
browsers. Narrow layouts place the hint above the footer without overlapping
commands. The live engine, combat and save isolation are unchanged.

Fresh deployments restore 21 published engine artifacts, pinned by source,
recipe, size and SHA-256. Only changed engine recipes compile Crawl. A temporary
empty-directory restore took 1.018 seconds locally; this is not a claim about
Cloudflare's end-to-end deployment time. App outputs are reused when inputs and
output files are unchanged. Publishing no longer runs duplicate Git guards or
a mandatory release suite; the optional guard and broad audit remain available.
GitHub PR checks remain, with full checks available by manual dispatch.

Validation: typecheck, 36 focused unit tests and 13 deployment tests passed.
Three production browser checks passed: shell/CSP, real menu combat/lifecycle,
and delayed loading/fallback transition. The narrow layout was adjusted after
visual inspection and its loading check passed again. Desktop/narrow screenshots
were reviewed. A production build and unchanged-build reuse both succeeded.
Full release/raster suites and engine E2E were intentionally not repeated for
this change. No authenticated-play or physical-device acceptance is claimed.
