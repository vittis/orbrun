# Release 0.3.113 — Window polish and canvas focus

Source version **0.3.113**, immutable source tag **`cloudflare-online-v1.110`**. UI implementation `fbfd8a7` is integrated with the concurrent 0.3.112 fog release and level-up snapshot-clock fix. Publication follows [DEPLOYMENT.md](../DEPLOYMENT.md): fresh-main guards, atomic non-force main/tag publication and the main-triggered Workers Build.

Gameplay windows open with a 130 ms opacity fade and close with a 90 ms fade. Retiring windows become inert immediately, stay outside the live focus/scroll stack and have bounded cleanup. Rebuilding server content preserves an entrance already in progress and never replays a settled entrance. Hover feedback changes paint without moving inventory or spell rows. Quick settings and backdrops transition smoothly; Still and OS reduced motion skip UI motion. The focused gameplay canvas keeps keyboard control without a browser focus outline. Control focus indicators remain visible.

## Validation

- Integrated `npm run verify:release` passed forced TypeScript, **2,504 unit/deployment tests**, the production build and **31 browser tests**, including the full raster matrix and production preview, with zero retries. Two optional-engine tests were skipped because their artifacts are unavailable.
- The focused browser regression verifies immediate canvas focus return, the absence of its outline and continued keyboard movement on desktop and narrow touch layouts. Window checks cover rebuild clocks, rapid reopening, inert retirement, cleanup, stable hover geometry and motion preferences.
- Reviewed the merged source against current main, whitespace and immutable source links. Existing non-fatal large-chunk build warnings remain. The current-main fog release and snapshot-clock fix remain intact.

Clean-tree guarded packaging and observed hosted identity follow acceptance, before deployment is reported successful.

Optional engine artifacts, authenticated play and physical-device acceptance are outside this coverage. Hosted source/version and bundle identity must match the release before deployment is reported successful. No manual deployment races Workers Builds.
