# Release 0.3.95 — Shield-blocked melee bumps

Source version **0.3.95**, immutable source tag **`cloudflare-online-v1.92`**. Publication follows [DEPLOYMENT.md](../DEPLOYMENT.md) through automatic Workers Builds.

Explicit melee block messages now produce a confirmed blocked-attempt event. An identifiable visible attacker bumps toward the recipient, and the existing shield contact cue appears at the shared bump contact time. Blocks never produce damage flashes, impact ripples, material spray or invented HP amounts. Player, enemy and ally attacks use the same path, retaining Still/reduced motion, visibility/reach checks and rollback deduplication.

The separate duplicate-name limitation remains: if several visible creatures with the same name could have made an attack, an ordinary WebTiles message does not identify which one attacked. The client retains its unambiguous-source safeguard instead of attributing an attack to every matching creature. This release does not claim to resolve that case from the reported screenshot.

Integrated **0.3.94 / `987a1c2`**, preserving the concurrent quick-settings focus repair. Only this checkout was modified. Publication uses a non-forced atomic main/tag push after a fresh remote check; no manual upload races automatic Workers Builds.
