# Release 0.3.121 — Creature movement

Source version **0.3.121**, immutable source tag **`cloudflare-online-v1.118`**.
This release builds on `1cb751a` (0.3.120). The
[source tag](https://github.com/vittis/orbrun/tree/cloudflare-online-v1.118)
identifies the release commit. Publication follows [DEPLOYMENT.md](../DEPLOYMENT.md):
clean-tree/current-main guards, atomic non-force publication of main and the tag,
and the main-triggered Workers Build.

Confirmed creature movement adds hops, slime compression, slithering, scuttling,
undead shuffles and flying banks without lifting the camera or changing cells.
Retargets preserve the current body pose. Player species and confirmed form
artwork distinguish non-walking bodies; actual flight takes precedence.
Still/reduced motion, visibility boundaries and flat supporting maps are retained.

Settings → View and Tune → View expose independent movement strengths and finer
10 ms duration steps. Defaults are **40% hop height, 60% squash and 100% sway**.
Preferences apply live, persist, reset and survive map transitions. Player/allied
ground circles are removed; shadows and targeting indicators remain. Settings
rows defer pointer focus until click to prevent changing hint height from moving
a pressed row before mouseup.

The complete `npm run verify:release` gate passed using Git Bash as npm's script
shell on Windows: forced TypeScript, **2,553 unit/deployment tests**, one production
build and **37 browser/production tests**, with zero retries. Two optional-engine
tests skipped because their artifacts are not provisioned. The full movement
matrix includes **1,134 checks** covering poses, tuning, picking, camera following,
continuity and landing. The existing large-chunk build warning remains non-fatal.

The audio lifecycle
test now closes its native select popup after the unlocking gesture; all playback
assertions already passed, but Windows Chromium context teardown failed while
the popup remained open. The corrected targeted test passes with zero retries.

No authenticated-play, physical-device, physical-audio or optional-engine
acceptance is claimed. Hosted source/version and bundle identity must match this
tag before deployment is reported successful.
