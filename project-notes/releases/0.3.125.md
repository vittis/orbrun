# 0.3.125 — Faster repeat visits and raw menu rendering

Source tag: `cloudflare-online-v1.122`.

Menu startup uses a build-pinned manifest embedded in the app bundle, starts
artwork and the engine concurrently, and compiles Wasm while other engine data
loads. Immutable assets use a dedicated versioned CacheStorage cache (current
and one prior build). Cache denial/eviction falls back to HTTP. Saves, accounts
and encounter state remain untouched; the engine still uses disposable memory.

The supported Emscripten `instantiateWasm` hook consumes the already loaded
binary/module. The generated loader ignored the former `wasmBinary` property
and downloaded Wasm again. Cloudflare also now preserves asset 304 responses;
the previous handler turned conditional repeat-visit requests into 404s.

Removed the full-menu dimming overlay. The live canvas displays the renderer's
actual colors and lighting. Still/reduced motion retains the quiet entrance.
Cancellation terminates a worker even if its artwork has not finished loading.

Validation: typecheck; 57 focused unit tests; all 41 real-engine E2E tests; and
four relevant production-browser scenarios (shell/CSP, live combat/lifecycle,
slow loading/cancellation, repeat visits). The repeat-visit scenario blocks all
large engine/gamedata network requests after warming and still renders live
play. No wall-clock performance assertion was added to CI. Desktop output was
visually inspected. Full release/raster suites were not repeated; no physical
mobile-device or authenticated-player acceptance is claimed.
