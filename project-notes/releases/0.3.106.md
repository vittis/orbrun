# Release 0.3.106 — Venom weapon hit and death feedback

Source version **0.3.106**, immutable source tag **`cloudflare-online-v1.103`**. The implementation is commit `36de74f`, retaining main through `2776bba` and all earlier agents’ work. Publication follows [DEPLOYMENT.md](../DEPLOYMENT.md) using fresh-main guards and an atomic, non-force push to the main-triggered Workers Build.

Known venom branding on the player’s primary weapon is captured when a confirmed weapon-hit message arrives. It supplies poison appearance to the existing hit spray and retained killing-hit evidence, including lethal strikes that emit no separate poison-status sentence. It does not assert extra poison damage or a newly applied status. Capture at receipt preserves the hit’s appearance if the weapon changes before the next rendered frame.

Crawl’s [brand handling](https://github.com/crawl/crawl/blob/stone_soup-0.34/crawl-ref/source/attack.cc) applies venom through poisoning and skips its extra effect on an already dead defender. Its [poison messages](https://github.com/crawl/crawl/blob/stone_soup-0.34/crawl-ref/source/beam.cc) describe status changes rather than the burning/freezing extra-damage wording. Matching known ordinary and artifact brand descriptions fixes the missing appearance without turning those status messages into additional hits. Auxiliary attacks, other actors’ hits, spells, misses, zero damage and unknown killing hits retain their own evidence.
