# Release 0.3.82 — Confirmed incoming hits

Source version **0.3.82**, immutable source tag **`cloudflare-online-v1.79`**. Publication uses the main-triggered Workers Builds path in [DEPLOYMENT.md](../DEPLOYMENT.md).

Player hit flashes and impact effects now require a confirmed incoming melee or spell result. An HP decrease alone no longer establishes a hit, so Djinni spell previews, cancelled previews and HP casting costs cannot trigger it. Incoming combat messages remain independent of HP update ordering, including casts and enemy attacks in the same turn. Explicit zero-damage results, misses, blocks and replayed message suffixes do not emit hits. Ordinary server messages provide qualitative intensity; only explicitly reported numbers provide damage amounts.

Integrated on `fff0ecb` (0.3.81), preserving concurrent animation smoothing, wider death splatter and all previous terrain/spell changes. The deployment guard refused the earlier stale candidate before publication; release metadata was advanced without moving or reusing a tag. No other worktrees or servers were modified.
